Release notes are generated by `.github/workflows/release.yml`:

- If `release-notes/<tag>.md` exists (e.g. `release-notes/v0.8.md`), its content is
  used verbatim as the "What's changed" section — use this for hand-written,
  user-facing summaries.
- Otherwise the workflow builds the section automatically from the commit log
  since the previous tag (`git log --pretty='- %s (%h)' prev..tag`).

The notes are what the dashboard shows under an available update, so keep them
short and user-readable (features, fixes, device-side changes, caveats).
